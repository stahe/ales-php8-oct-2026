    Vamos a explorar ahora cómo estructurar una aplicación PHP en capas:

    En este diagrama, la capa de la izquierda inicia el uso de la capa de la derecha. Los roles de las capas son los siguientes:

    • [1]: la capa llamada [dao] (Data Access Objects) gestiona las interacciones con los almacenes de datos externos [4] (archivos, bases de datos, servicios web, etc.). A esta capa se la llama a veces [DAL] (Data Access Layer), un término que describe mejor su rol. Esta capa puede leer datos de [3] o escribir datos en [2]. La llama la capa [business] [6] y le devuelve resultados [7];
    • [5]: una capa llamada [business] que reúne los procedimientos “de negocio” y recibe todos los datos que necesitan. Suele ser la capa más estable de un proyecto, porque no depende de cómo se obtienen los datos. Los datos provienen de dos fuentes:
      • [9]: datos proporcionados por el script PHP;
      • [6, 7]: datos solicitados a la capa [dao];
    • [8]: el script principal actúa como orquestador. En una aplicación de consola, este:
      • crea las capas [business] y [dao];
      • ejecuta el algoritmo de la aplicación. Este algoritmo funciona como un orquestador: no contiene “lógica de negocio” ni código de acceso a datos. El script principal se limita a llamar a los procedimientos de la capa [business] [9]. Ignora por completo la capa [dao] y los datos externos. Puede proporcionar a la capa [business] datos [9]. En una aplicación de consola, estos datos pueden provenir de archivos de configuración o del usuario del script. Recibe resultados [10] de la capa [business]. Puede necesitar almacenar ciertos resultados: para ello, utiliza de nuevo los procedimientos de la capa [business], que a su vez recurrirá a la capa [dao] para realizar la tarea;
      • Entre los resultados, el script principal puede recibir excepciones. Corresponde al script principal gestionar las excepciones que se propagan desde todas las capas.

    Esta arquitectura en capas está diseñada para facilitar la evolución de la aplicación. Para lograrlo, cada capa implementa una interfaz. Supongamos que:

    • la capa [dao] está implementada por una clase [Dao], que implementa una interfaz [IDao];
    • la capa [business] está implementada por una clase [Business], que implementa una interfaz [IBusiness].

    Los procedimientos de la capa [business] usarán entonces la interfaz [IDao] en lugar de la clase [Dao]. Esto permite actualizar la capa [dao] sin afectar a la capa [business]. Supongamos que en la versión 1, la capa [Dao1] usa datos de una base de datos. Tras una actualización, esos datos ahora los proporciona un servicio web en la versión 2, [Dao2]. Nos aseguraremos de que ambas clases, [Dao1] y [Dao2], implementen la misma interfaz, [IDao], y lancen las mismas excepciones. Si esto se cumple, la capa [Business], que trabaja con la interfaz [IDao], permanecerá sin cambios.

    El mismo razonamiento se aplica a la capa [business].

    • línea 9: la persona tiene un solo atributo, su identificador [$id], inicializado por el constructor mediante la promoción de parámetros. Supondremos que este identificador designa a una persona única en un almacén de datos;
    • líneas 14–17: el método [__toString], que muestra el identificador de la persona.

    La capa [business] proporciona la siguiente interfaz [IBusiness]: [IBusiness.php]:

    <?php

declare(strict_types=1);

// capa [business] ────────────────────────
interface IBusiness extends IDao
{
    // procesamos una persona
    public function doSomething(Person $p): void;
}

    Comentarios

    • línea 6: la interfaz [IBusiness] extiende la interfaz [IDao]. Esto no es en absoluto obligatorio. Lo hacemos aquí porque el ejemplo es simple: la capa [business] proporciona al script principal los métodos [get] y [save] de la capa [dao], que le oculta al script principal;
    • línea 9: el método [doSomething] es específico de la capa [business].

    El curso de PHP 7 se refería a la interfaz [IMétier] y a la clase [Métier], con acento. PHP admite letras acentuadas en los identificadores, pero un archivo llamado [Métier.php] causa problemas con ciertas herramientas (archivos ZIP, sistemas de archivos, carga automática de clases). Ahora nos atenemos a nombres de clases y de archivos sin acentos: aquí, [IBusiness] y [Business].

    <?php

declare(strict_types=1);

final class Business implements IBusiness
{
    // la capa [dao] se inyecta por el constructor
    public function __construct(private readonly IDao $dao)
    {
    }

    // procesamos una persona
    #[\Override]
    public function doSomething(Person $p): void
    {
        // procesamiento
        print "[Business]: Business processing of the person $p\n";
    }

    // guardado de la persona
    #[\Override]
    public function save(Person $p): void
    {
        print "[Business]: Saving the person $p\n";
        // pedimos a la capa [dao] que haga el guardado
        $this->dao->save($p);
    }

    // recuperación de una persona
    #[\Override]
    public function get(int $id): Person
    {
        print "[Business]: Retrieving the person with identifier $id\n";
        // pedimos la persona a la capa [dao]
        return $this->dao->get($id);
    }
}

    Comentarios

    • línea 8: la capa [business] debe tener una referencia a la capa [dao] para poder usar los métodos de esta. Esa referencia se le pasa mediante su constructor y se almacena en el atributo privado de solo lectura [$dao] (promoción de parámetros). Observe que el tipo del parámetro es la interfaz [IDao]. Así, la capa [business] podrá trabajar con cualquier clase que implemente la interfaz [IDao]. Si pasamos de una capa [Dao1] a una capa [Dao2], y ambas implementan la interfaz [IDao], no hace falta reescribir la capa [business];
    • esta técnica se denomina inyección de dependencias por constructor: la clase [Business] no crea la capa [dao] de la que depende; en su lugar, se le proporciona. El curso de PHP 7 usaba un setter [setDao]. La inyección por constructor es ahora la norma: un objeto [Business] no puede existir sin su capa [dao], y esta capa no puede cambiarse después (atributo [readonly]). Este es también el enfoque adoptado por frameworks como Symfony o Laravel;
    • líneas 14–18: implementación de [IBusiness::doSomething];
    • líneas 22–27: implementación de [IBusiness::save]. Este método debe guardar una persona en un almacén de datos. La capa [business] no puede hacerlo. Recurre a la capa [dao] para realizar ese guardado (línea 26);
    • líneas 31–36: implementación de [IBusiness::get]. Este método debe recuperar de un almacén de datos a la persona cuyo identificador se le pasa como parámetro. La capa [business] no puede hacerlo. Recurre a la capa [dao] para realizar la tarea (línea 35).

    Conclusión: siempre que la capa [business] necesite acceder a datos almacenados en el almacén de datos, debe pasar por la capa [dao], creada específicamente para acceder a esos datos.

    Escribiremos dos scripts de orquestación para esta aplicación. El primero, [main1.php], usará la capa [Dao1], mientras que el segundo, [main2.php], usará la capa [Dao2]. Queremos mostrar que esto no tiene ningún impacto en el código de la capa [Business].

    <?php

// respeto estricto de los tipos declarados de los parámetros y resultados de las funciones
declare(strict_types=1);

// inclusión de las clases e interfaces
require_once __DIR__ . "/Person.php";
require_once __DIR__ . "/IDao.php";
require_once __DIR__ . "/IBusiness.php";
require_once __DIR__ . "/Dao1.php";
require_once __DIR__ . "/Business.php";

// creación de las capas: la capa [dao] se inyecta en la capa [business]
$business = new Business(new Dao1());
// uso de la capa [business]
$person = $business->get(4);
$business->doSomething($person);
$business->save($person);

    Comentarios

    • El script [main1.php] actúa como orquestador de la aplicación. Carga los archivos de clases e interfaces (líneas 7–11), crea la estructura en capas de la aplicación (línea 14) y luego se comunica con la capa [business] (líneas 16–18);
    • línea 14: es aquí, y solo aquí, donde se elige la implementación de la capa [dao];
    • Según el diagrama de la estructura en capas, el script [main1.php] debe comunicarse únicamente con la capa [business]. No debe comunicarse con la capa [dao], aunque esto sea teóricamente posible.
