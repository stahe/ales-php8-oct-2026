// esto es un comentario

}
// inicialización de 2 variables con el contenido de un arreglo

// concatenación de las 2 cadenas
$string3 = $string1 . $string2;

// una función puede devolver un resultado

print "res1=$res1\n";
// una función puede devolver un arreglo de valores
[$res1, $res2, $res3] = f2();
print "(res1,res2,res3)=[$res1,$res2,$res3]\n";
// habríamos podido recuperar estos valores en un arreglo
$t = f2();
for ($i = 0; $i < count($t); $i++) {
    print "t[$i]=$t[$i]\n";
}
// algunas pruebas
for ($i = 0; $i < count($t); $i++) {
    // solo muestra las cadenas
    if (gettype($t[$i]) === "string") {
        print "t[$i]=$t[$i]\n";
    }
}
// operadores de comparación == y ===
if ("2" == 2) {
    print "with the == operator, the string 2 is equal to the integer 2\n";
} else {
    print "with the == operator, the string 2 is not equal to the integer 2\n";
}
if ("2" === 2) {
    print "with the === operator, the string 2 is equal to the integer 2\n";
} else {
    print "with the === operator, the string 2 is not equal to the integer 2\n";
}
// una comparación cuyo resultado cambió con PHP 8
if (0 == "abc") {
    print "with the == operator, the integer 0 is equal to the string abc\n";
} else {
    print "with the == operator, the integer 0 is not equal to the string abc\n";
}
// otras pruebas
for ($i = 0; $i < count($t); $i++) {
    // solo muestra los enteros > 10
    if (is_int($t[$i]) && $t[$i] > 10) {
        print "t[$i]=$t[$i]\n";
    }
}
// un bucle while
$t = [8, 5, 0, -2, 3, 4];
$i = 0;
$sum = 0;
while ($i < count($t) && $t[$i] > 0) {
    print "t[$i]=$t[$i]\n";
    $sum += $t[$i];   // $sum = $sum + $t[$i]
    $i++;             // $i = $i + 1
}
print "sum=$sum\n";

// fin del programa
exit;

    print "string=$string\n";
}

    print "type[variable $" . $name . "]=" . gettype($variable) . "\n";

{
    // suma 10 a $param
    return $param + 10;
}

//----------------------------------
function f2(): array

    // devuelve 3 valores

    Comentarios:

    • línea 4: indica a PHP que verifique estrictamente los tipos declarados de los parámetros y de los valores de retorno de las funciones. Volveremos sobre esto en la sección sobre los cambios de tipo. Por ahora, tenga en cuenta que todos los scripts de este curso comienzan así;
    • línea 8: en PHP las variables no se declaran. Tienen un tipo dinámico que puede cambiar con el tiempo. [$name] representa la variable con el identificador [name];
    • línea 10: para escribir en pantalla se puede usar la instrucción [print] o la instrucción [echo];
    • línea 12: la notación [[...]] sirve para definir un arreglo. La notación [$array[$i]] representa el elemento n.º [$i] del arreglo [$array], donde el primer elemento tiene el número 0. La notación más antigua [array("one", "two", 3, 4)] todavía se acepta, pero no la usaremos;
    • línea 14: la función [count($array)] devuelve el número de elementos del arreglo [$array];
    • líneas 16 a 18: un bucle. Como este bucle contiene una sola instrucción, las llaves son opcionales. En el resto de este documento, usaremos siempre llaves, sin importar el número de instrucciones;
    • línea 17: las cadenas se delimitan con comillas dobles " o comillas simples '. Dentro de las comillas dobles, las variables [$variable] se evalúan (también se dice que se “interpolan”), pero no dentro de las comillas simples;
    • línea 20: se pueden asignar los elementos de un arreglo a varias variables en una sola operación. Aquí, [$string1="string1"] y [$string2="string2"]. Esta sintaxis, llamada desestructuración, reemplaza a la función [list] de las versiones antiguas de PHP: [list($string1, $string2) = ...] todavía se acepta;
    • línea 22: el operador . (punto) es el operador de concatenación de cadenas;
    • líneas 91 a 95: la palabra clave [function] define una función. Una función puede definirse en cualquier parte del script, incluso después de haber sido utilizada. Aquí, [string $string] indica que el parámetro [$string] debe ser una cadena, y [: void] indica que la función no devuelve ningún resultado. Estas declaraciones de tipo son opcionales en PHP, pero las usaremos de manera sistemática: documentan el código y permiten que PHP (y el editor) detecten errores;
    • línea 98: el tipo [mixed] (PHP 8.0) significa “cualquier tipo”. El parámetro [$variable] puede aceptar un entero, una cadena, un arreglo, etc.;
    • línea 101: la función predefinida [gettype($variable)] devuelve una cadena que representa el tipo de [$variable]. Los resultados muestran que este tipo puede cambiar con el tiempo: [$n] es primero un entero y luego una cadena;
    • línea 105: una función devuelve un resultado mediante la instrucción [return]. El tipo de este resultado se declara después de los paréntesis: [: int]. El código que realiza la llamada puede ignorar o recuperar los resultados de una función;
    • línea 112: una función puede devolver varios valores agrupándolos en un arreglo;
    • líneas 53 a 62: el operador [===] realiza una comparación estricta de dos elementos: deben tener el mismo tipo y el mismo valor para ser iguales. El operador [] es menos estricto: dos elementos pueden ser iguales sin ser del mismo tipo. En ese caso, la comparación se realiza después de convertir ambos elementos al mismo tipo. Es bastante fácil “pasar por alto” estas conversiones implícitas y terminar con resultados inesperados, como descubrir que una condición es verdadera cuando se esperaba que fuera falsa. Para evitar esta trampa, usaremos de manera sistemática el operador de comparación [=] (y su negación, [!==]);
    • líneas 64 a 68: un ejemplo de estas conversiones implícitas. En PHP 7, la cadena “abc” se convertía en el número 0, ¡y la expresión [0 == "abc"] era verdadera! Desde PHP 8.0, al comparar un número con una cadena que no representa un número, el número se convierte en cadena y la expresión es falsa. El comportamiento de [] ha cambiado, por lo tanto, de una versión a otra: razón de más para preferir [=];
    • línea 72: la función [is_int] devuelve [true] si su parámetro es un entero. De manera similar, existen [is_string], [is_float], [is_bool], [is_array]… El operador [&&] es el AND lógico. También se pueden usar los operadores lógicos [||] (OR) y [!] (NOT). PHP también admite las palabras clave [and] y [or], pero su menor prioridad respecto de la asignación puede dar lugar a resultados inesperados: no las usaremos;
    • línea 80: un bucle [while]. Se detiene en cuanto la condición es falsa; en este caso, en cuanto se recorre el arreglo o se encuentra un elemento negativo o igual a cero;
    • línea 88: la instrucción [exit] detiene la ejecución del script. Las funciones que siguen no se ejecutan en ese punto, pero son reconocidas por todo el script.

    Observe que el script no termina con la etiqueta de cierre [?>] del código PHP. No es indispensable. Además, en un contexto web puede causar problemas si va seguida de espacios o saltos de línea, que son difíciles de detectar porque no son visibles en un editor de texto. De hecho, la recomendación [PSR-12] especifica que debe omitirse en los archivos que solo contienen PHP. Por lo tanto, en el resto de este documento la omitiremos de forma sistemática.

    Nota: en este documento usaremos la palabra clave [print] para mostrar texto en la consola. Otra forma de hacer lo mismo es usar la palabra clave [echo]. Existen diferencias sutiles entre estas dos palabras clave, pero en el contexto de este documento no habrá ninguna. Así que, si prefiere usar [echo], adelante.

    3.3.2. Uso de VS Code

    Para trabajar con los scripts del curso, abra la carpeta [php8-oct-2026] en [VS Code] (menú [File > Open Folder]). El árbol de archivos aparece en el explorador, en el lado izquierdo de la ventana. Para ejecutar un script:

    • abra un terminal integrado (menú [Terminal > New Terminal]). Se abre en la carpeta [php8-oct-2026];
    • navegue a la carpeta del script: [cd scripts-console/basics];
    • ejecute el script: [php basics-01.php]. Los resultados se muestran en el terminal. Como alternativa, en el explorador de archivos puede hacer clic con el botón derecho en la carpeta [basics] y seleccionar [Open in Integrated Terminal].

    Si el comando [php] no se reconoce, significa que la carpeta de PHP no está incluida en el PATH de Windows: [Laragon] la agrega allí cuando se marca la opción correspondiente en su menú [Tools > Path]. El comando [php -v] debería mostrar la versión 8.5.

    La extensión [PHP Intelephense] analiza el código mientras se escribe y señala los problemas con una línea ondulada bajo el código incorrecto. Al pasar el mouse sobre esta línea se muestra el mensaje. Todos los problemas del archivo se listan en el panel [Problems] (menú [View > Problems]). Entre las advertencias útiles se encuentran:

    • [Undefined variable]: se está usando una variable sin haberla inicializado. A menudo es un error tipográfico en el nombre de la variable;
    • [Undefined function]: se está llamando a una función que no existe; de nuevo, suele ser un error tipográfico;
    • [Expected type 'int'. Found 'string'.]: un parámetro real no tiene el tipo declarado por la función. Esta es una de las grandes ventajas de las declaraciones de tipo: el error se informa incluso antes de la ejecución;
    • [Expected 2 arguments. Found 1.]: el número de parámetros reales no coincide con la definición de la función.

    Al pasar el mouse sobre el nombre de una función se muestra su firma (parámetros, tipos, valor de retorno) y su documentación, incluso para las funciones predefinidas de PHP. Para asegurarse de que [Intelephense] conozca las novedades recientes del lenguaje, revise la configuración de [VS Code] (menú [File > Preferences > Settings], busque “intelephense php version”) y verifique que la versión de PHP especificada sea la 8.5. Mientras aprende el lenguaje, se aconseja corregir todas las advertencias que se informen. Es una excelente manera de aprender.

    [Intelephense] también puede formatear un archivo (clic con el botón derecho, [Format Document]) según las recomendaciones de codificación de [PSR-12]. Las PSR (PHP Standard Recommendations) son guías para producir código estándar, lo que facilita la interoperabilidad y el mantenimiento del código escrito por distintas personas. Las publica el [PHP-FIG] en el sitio web www.php-fig.org. Las recomendaciones [PSR-1] y [PSR-12] establecen las reglas para escribir código. Estas son las reglas de [PSR-1]:

    Elemento
    Regla
    Constantes de clase
    Las constantes de clase DEBEN escribirse en mayúsculas, con el carácter _ como separador.
    Ej.: [const VAT_RATE]
    Métodos
    Los nombres de los métodos DEBEN escribirse en camelCase.
    Ejemplo: [public function executeBatchTaxes()]
    Propiedades
    Los nombres de las propiedades DEBERÍAN escribirse de manera coherente dentro de una misma base de código, en StudlyCaps, camelCase o under_score.
    Ejemplos: [$AnnualSalary], [$annualSalary], [$annual_salary]
    Efectos secundarios
    Un archivo DEBERÍA declarar nuevos símbolos (clases, funciones, constantes, etc.) sin ningún efecto secundario, o bien ejecutar código con efectos secundarios, pero NO DEBERÍA hacer ambas cosas.
    Tipos
    Los nombres de los tipos (clases, interfaces, etc.) DEBEN escribirse en StudlyCaps. Cada tipo está en su propio archivo y en un espacio de nombres con al menos un nivel.
    Ejemplo: [class ScholarshipStudent]

    La regla de los efectos secundarios establece que un archivo debe contener:

    • o bien declaraciones de tipos (clases, interfaces), funciones o constantes;
    • o bien código ejecutable sin declaraciones de nuevos tipos.

    Para simplificar, los ejemplos de este capítulo no siguen esta regla: cada script es un único archivo que define sus funciones y las utiliza. Dividir el código en varios archivos resultaría demasiado engorroso para ejemplos básicos. En la aplicación presentada como hilo conductor de este documento, nos esforzaremos por seguir estas recomendaciones lo más fielmente posible una vez que esté escrita con clases.

Observe que [usort] modifica el arreglo que se le pasa (paso por referencia): por lo tanto, hemos ordenado una copia ([$sorted]) del arreglo [$numbers];
    • línea 35: las funciones [array_find], [array_any] y [array_all] se introdujeron con PHP 8.4. [array_find] devuelve el primer elemento para el cual la función devuelve [true] (o [null] si no hay ninguno), [array_any] devuelve [true] si al menos un elemento cumple la condición, y [array_all] si todos la cumplen;
    • línea 40: sintaxis de callable de primera clase (PHP 8.1): [functionName(...)], con tres puntos entre los paréntesis, no llama a la función sino que devuelve la función misma como un objeto [Closure]. Luego se puede utilizar como una función anónima;
    • línea 43: la función predefinida [ucfirst] (primera letra en mayúscula) se pasa a [array_map];
    • líneas 46–49: el operador pipe [|>] (PHP 8.5). La expresión [value |> function] llama a la función con el valor como único parámetro.     $line = cutNewLineChar($line);
    // colocamos la línea en un arreglo
    $info = explode(":", $line);
    // recuperamos el login
    $login = array_shift($info);
    // ignoramos el pwd
    array_shift($info);
    // creamos una entrada en el diccionario
    $dict[$login] = $info;

// --------------------------------------------------------------------------
function displayInfo(array $dict, string $key): void
{
    // muestra el valor asociado a key en el diccionario $dict si existe
    if (isset($dict[$key])) {
        // el valor existe - ¿es un arreglo?
        $value = $dict[$key];
        if (is_array($value)) {
            print "[$key," . implode(":", $value) . "]\n";
        } else {
            // $value no es un arreglo
            print "[$key,$value]\n";
        }
    } else {
        // $key no es una clave del diccionario $dict
        print "the key [$key] does not exist\n";
    }
}

// --------------------------------------------------------------------------
function cutNewLineChar(string $line): string
{
    // eliminamos la marca de fin de línea de $line si existe
    // (\n en Unix, \r\n en Windows)
    return rtrim($line, "\r\n");
}

    • línea 12: [fopen(file_name, "w")] abre el archivo [file_name] en modo de escritura (w=write). Si el archivo no existe, se crea. Si existe, se vacía. El archivo se crea en el directorio actual, aquel desde el que se ejecutó el script. Si la creación falla, [fopen] emite una advertencia y devuelve el valor [false];
    • línea 13: el resultado de [fopen] se prueba comparándolo estrictamente con [false];
    • línea 19: [fputs($file, $string)] escribe [$string] en el archivo [$file]. Aquí, la cadena termina con el marcador de fin de línea [\n];
    • línea 22: [fclose($file)] cierra el archivo [$file];
    • línea 27: [fopen(file_name, "r")] abre el archivo [file_name] en modo de lectura (r=read). Si la apertura del archivo falla (por ejemplo, si el archivo no existe), [fopen] devuelve el valor [false];
    • línea 34: el diccionario se inicializa vacío antes de llenarlo. PHP crearía el arreglo en la primera asignación de [$dict[$login] = ...], pero si el archivo estuviera vacío, la variable no existiría y su uso provocaría una advertencia;
    • línea 38: [fgets($file, 1000)] lee la siguiente línea del archivo, limitada a 1,000 caracteres. La operación [while (($line = fgets($file, 1000)) !== false) {...}] consta de dos operaciones sucesivas: 1) [$line = fgets(...)] y 2) [while ($line !== false)]. Después de leer el último carácter del archivo, la función [fgets] devuelve el valor [false], y el bucle [while] se detiene. Aquí, la función [fgets] intenta leer hasta 1,000 caracteres pero se detiene en cuanto encuentra un carácter de fin de línea. Como todas las líneas tienen aquí menos de 1,000 caracteres, [fgets] lee una línea de texto, incluido el carácter de fin de línea. El curso de PHP 7 escribía [while ($line = fgets($file, 1000))]: el bucle se habría detenido prematuramente ante una última línea reducida a "0", sin carácter de fin de línea, porque la cadena "0" se convierte en [false]. La comparación estricta [!== false] evita esta trampa;
    • línea 40: la función [cutNewLineChar] elimina los caracteres de fin de línea, si los hay;
    • línea 44: la función [array_shift($array)] elimina el primer elemento de [$array] y lo devuelve como resultado;
    • línea 46: aquí ignoramos el resultado devuelto por [array_shift];
    • línea 58: otra forma de leer un archivo de texto. La función [file] devuelve un arreglo que contiene todas las líneas del archivo. Con la opción [FILE_IGNORE_NEW_LINES], se eliminan los caracteres de fin de línea. Es más simple que el bucle con [fgets], pero todo el archivo se carga en memoria: para un archivo muy grande, es preferible leer línea por línea;
    • línea 71: la función [is_array($variable)] devuelve [true] si [$variable] es un arreglo, y [false] en caso contrario;
    • línea 84: el carácter de fin de línea es la cadena "\r\n" en los sistemas Windows y "\n" en los sistemas Unix. La función [rtrim($string, $characters)] elimina todos los caracteres presentes en [$characters], en este caso \r y \n, del final de [$string]. Sin un segundo parámetro, [rtrim] elimina todos los “espacios” (espacios en blanco, tabulaciones, saltos de línea, etc.); la función [trim] hace lo mismo en ambos extremos de la cadena.
