    9. Traits

    Los traits son estructuras análogas a las clases. Sin embargo, no se pueden instanciar: están destinados a incluirse en clases. Incluir un trait en una clase tiene el mismo efecto que si el código del trait se hubiera copiado en la clase. El código que puede reutilizarse en varias clases se coloca en un trait.

    Los traits existen desde PHP 5.4. PHP 8 introdujo varias novedades, que veremos al final de este capítulo: verificación de firmas para métodos abstractos (PHP 8.0), constantes en traits (PHP 8.2), el atributo [#[\Override]] utilizable en un trait (PHP 8.3).

    <?php

declare(strict_types=1);

class Class04
{
    // constructor con promoción del atributo [name]
    public function __construct(private string $name)
    {
    }

    // getter y setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

trait Trait04
{
    // atributo
    private string $name;

    // getter y setter
    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $this->name = $name;
    }
}

class Class05
{
    // inclusión del trait
    use Trait04;

    // constructor
    public function __construct(string $name)
    {
        $this->name = $name;
    }
}

// prueba ──────────────
$class04 = new Class04("Tim");
$class05 = new Class05("Burton");
print $class04->getName() . "\n";
print $class05->getName() . "\n";
// visualización de los dos objetos
print_r($class04);
print_r($class05);

    Comentarios del código

    • líneas 5–22: definición de la clase [Class04] con un atributo [$name] (inicializado por el constructor), su getter y su setter;
    • líneas 24–39: tomamos el código de [Class04]—sin su constructor— y lo trasladamos al trait [Trait04]. Esta vez el atributo se declara explícitamente, junto con su tipo. No incluimos el constructor, ya que un trait no se puede instanciar;
    • línea 24: la palabra clave [trait] designa a [Trait04] como un trait y no como una clase;
    • líneas 41–51: definimos una clase [Class05] que incluye el código del trait [Trait04] y le agrega un constructor, para que la clase sea instanciable;
    • línea 44: la palabra clave [use], colocada dentro de una clase, permite incluir un trait en ella. No debe confundirse con la instrucción [use], que se coloca fuera de cualquier clase e importa un nombre de un espacio de nombres;
    • líneas 54–60: las pruebas muestran que las clases [Class04] y [Class05] funcionan de la misma manera.

    <?php

declare(strict_types=1);

trait Trait01
{
    // atributo
    private int $id = 0;

    // método
    public function doSomething(): void
    {
        print "Trait01::doSomething... ($this->id)\n";
    }
}

class Class02
{
    // inclusión de Trait01
    use Trait01 {
        // el método [Trait01::doSomething] es accesible
        // en la clase con el nombre [doSomethingInTrait]
        Trait01::doSomething as doSomethingInTrait;
    }

    // método propio de la clase
    public function doSomething(): void
    {
        // atributo id
        $this->id += 10;
        // uso del método de Trait01
        $this->doSomethingInTrait();
        // visualización local
        print "Class02->doSomething\n";
    }
}

class Class03
{
    // inclusión de Trait01
    use Trait01;

    // método local de la clase
    public function doSomethingElse(): void
    {
        // atributo id
        $this->id += 10;
        // uso del método de Trait01
        $this->doSomething();
        // visualización local
        print "Class03->doSomethingElse\n";
    }
}

// test01 ────────────────
function test01(): void
{
    $class02 = new Class02();
    $class03 = new Class03();
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();

    Comentarios

    • líneas 5–15: un trait que define un atributo [$id] y un método [doSomething];
    • el trait [Trait01] se incluye en dos clases: [Class02] (líneas 17–36) y [Class03] (líneas 38–53);
    • líneas 20–24: inclusión de [Trait01] en [Class02]. A la inclusión le sigue un bloque [{...}] que permite ajustar los métodos incluidos;
    • línea 23: esta línea resuelve un conflicto: [Trait01] y [Class02] tienen ambos un método llamado [doSomething]. En este caso, el método de la clase tiene prioridad: el método del trait queda oculto. El operador [as] hace que el método [Trait01::doSomething] sea accesible en la clase con el nombre [doSomethingInTrait]. Así, dentro de [Class02], se usarán las siguientes notaciones:
      • [doSomethingInTrait] para llamar al método [Trait01::doSomething];
      • [doSomething] para llamar al método [Class02::doSomething];
    • líneas 30–32: la clase [Class02] usa el atributo y el método de [Trait01] como si fueran propios;
    • líneas 38–53: la clase [Class03] es análoga a la clase [Class02]. La inclusión de [Trait01] es aquí más sencilla porque no hay conflicto entre los métodos de [Trait01] y de [Class03].

    <?php

declare(strict_types=1);

// clase que reemplaza al trait
class Class01
{
    // atributo
    private int $id = 0;

    // setter
    public function setId(int $id): void
    {
        $this->id = $id;
    }

    // getter
    public function getId(): int
    {
        return $this->id;
    }

    // método
    public function doSomething(): void
    {
        print "Class01::doSomething... ($this->id)\n";
    }
}

class Class02
{
    // una referencia a una instancia de Class01, inyectada por el constructor
    public function __construct(private readonly Class01 $class01)
    {
    }

    // método propio de la clase
    public function doSomething(): void
    {
        // modificación del atributo de Class01
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
        // uso del método de Class01
        $this->class01->doSomething();
        // visualización local
        print "Class02->doSomething\n";
    }
}

class Class03
{
    // una referencia a una instancia de Class01, inyectada por el constructor
    public function __construct(private readonly Class01 $class01)
    {
    }

    // método local de la clase
    public function doSomethingElse(): void
    {
        // modificación del atributo de Class01
        $id = $this->class01->getId();
        $id += 10;
        $this->class01->setId($id);
        // uso del método de Class01
        $this->class01->doSomething();
        // visualización local
        print "Class03->doSomethingElse\n";
    }
}

// test01 ────────────────
function test01(): void
{
    // dos objetos que accederán a dos instancias distintas de [Class01]
    $class02 = new Class02(new Class01());
    $class03 = new Class03(new Class01());
    // verificación
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test02 ────────────────
function test02(): void
{
    // instancia compartida de [Class01]
    $class01 = new Class01();
    // dos objetos que accederán a la misma instancia de [Class01]
    $class02 = new Class02($class01);
    $class03 = new Class03($class01);
    // verificación
    $class02->doSomething();
    $class03->doSomethingElse();
}

// test01
print "test01-----------------\n";
test01();
// test02
print "test02-----------------\n";
test02();

    Comentarios

    • Líneas 6–28: la clase [Class01] reemplaza al trait [Trait01]. El código de [Trait01] se incorporaba al código de las clases [Class02] y [Class03]. Aquí no ocurrirá así: se inyectará una referencia a un objeto [Class01] en las clases [Class02] y [Class03] . Los atributos de la clase [Class01] serán, por lo tanto, externos a los objetos [Class02] y [Class03] . Como el atributo [$id] es privado, es necesario proporcionar un getter y un setter. Esta es la primera diferencia con un trait: hay que crear código para acceder a los atributos privados de la clase. Podríamos haber hecho público el atributo [$id], pero no se recomienda: usar un setter para asignar el valor de un atributo permite validarlo;
    • línea 33: la referencia al objeto *[Class01] se inyecta en *[Class02] mediante su constructor, gracias a la promoción de parámetros. El curso de PHP 7 usaba un setter [setClass01]. La inyección por el constructor es preferible: el objeto [Class02] está completo desde que se construye y, como el atributo es [readonly], la referencia ya no puede cambiarse;
    • líneas 41–45: para cualquier uso del código de [Class01], debemos pasar por el atributo [$this->class01];
    • líneas 51–70: la clase [Class03] es un clon de la clase [Class02], salvo que su método tiene un nombre distinto;
    • líneas 73–81: la primera prueba. Consiste en inyectar dos instancias distintas de la clase [Class01] en los objetos [Class02] y [Class03];
    • líneas 84–94: la segunda prueba inyecta la misma instancia de la clase [Class01] en los objetos [Class02] y [Class03].

Podemos concluir que, si se necesita compartir atributos entre objetos, no se puede usar el trait y debe usarse una clase en su lugar.

    9.4. Agrupación de métodos en un trait

    En el ejemplo anterior, el trait incluía atributos y métodos. Aquí consideraremos el caso en que contiene solo métodos. El trait se parece entonces a una factorización de métodos que pueden usarse en distintas clases. Como aquí el trait no tiene atributos, consideraremos el caso en que los métodos que contiene operan únicamente sobre los parámetros que reciben. Esto no es obligatorio: un trait puede operar sobre un atributo [$this->attribute1] sin tener él mismo ese atributo. En ese caso, corresponde a las clases que usan el trait proporcionar el atributo [$this->attribute1].

    Cuando el trait solo tiene métodos que operan únicamente sobre los parámetros que reciben, mostraremos que el trait puede sustituirse por una clase con los mismos métodos que el trait, declarados como estáticos.

Veremos al final del capítulo que PHP 8 ofrece una solución limpia para exigir algo a las clases que usan un trait: los métodos abstractos.

    9.5. Herencia múltiple con un trait

    Es común leer en la literatura que los traits permiten la herencia múltiple: la capacidad de una clase de heredar de varias clases. Mostraremos que, si bien usar un trait en una clase derivada permite implementar algo parecido a la herencia múltiple, este caso de uso también puede implementarse con clases simples.

declare(strict_types=1);

trait Trait01
{

    private int $i = 0;

    // método a compartir
    public function doSomethingInTrait01(): void
    {
        // modificación de Trait01::$i
        $this->i++;
        // visualización
        print "Trait01::doSomethingInTrait01... i=$this->i\n";
    }
}

class Class02
{
    // atributo accesible para las clases derivadas
    protected int $j = 0;

    // método
    public function doSomethingInClass02(): void
    {
        // modificación de Class02::$j
        $this->j += 10;
        // visualización
        print "Class02->doSomethingInClass02... j=$this->j\n";
    }
}

// clase derivada
class Class03 extends Class02
{
    // hereda Class02::$j e incluye Trait01::$i
    use Trait01;

    // método
    public function doSomethingInClass03(): void
    {
        // uso del método de Trait01

    9.6. Uso de un trait en lugar de una clase abstracta

    El siguiente caso de uso es común: se crea una interfaz I bastante general que puede dar lugar a varias implementaciones. Estas implementaciones comparten código común pero difieren en otros métodos. Hay dos maneras de implementar este caso de uso:

    • Se crea una clase abstracta C que contiene el código común a las clases derivadas. La clase C implementa la interfaz I, pero ciertos métodos —que deben definirse en las clases derivadas— se declaran abstractos en la clase C, que por lo tanto es a su vez abstracta. Luego se crean las clases C1 y C2 derivadas de C, cada una de las cuales implementa a su manera los métodos abstractos de su clase padre C;
    • se crea un trait T casi idéntico a la clase abstracta C de la solución anterior. Este trait no implementa la interfaz I porque, sintácticamente, no puede. Luego se crean las clases C1 y C2, que implementan la interfaz I y usan el trait T. A estas clases solo les resta implementar los métodos de la interfaz I que no están implementados por el trait T que importan.

    <?php

declare(strict_types=1);

interface Interface1
{
    public function doSomething(): void;

    public function doSomethingElse(): void;
}

abstract class AbstractClass implements Interface1
{
    // atributos accesibles para las clases derivadas
    protected int $attr1 = 11;
    protected int $attr2 = 12;

    // getters y setters
    public function getAttr1(): int
    {
        return $this->attr1;
    }

    public function getAttr2(): int
    {
        return $this->attr2;
    }

    public function setAttr1(int $attr1): static
    {
        $this->attr1 = $attr1;
        return $this;
    }

    public function setAttr2(int $attr2): static
    {
        $this->attr2 = $attr2;
        return $this;
    }

    // método implementado
    #[\Override]
    public function doSomething(): void
    {
        print "AbstractClass::doSomething [$this->attr1,$this->attr2]\n";
    }

    // método no implementado
    #[\Override]
    abstract public function doSomethingElse(): void;
}

// clase derivada 1
class Class1 extends AbstractClass
{
    // atributo
    private int $attr3 = 13;

    // getter y setter
    public function getAttr3(): int
    {
        return $this->attr3;
    }

    public function setAttr3(int $attr3): static
    {
        $this->attr3 = $attr3;
        return $this;
    }

    // implementación de doSomethingElse
    #[\Override]
    public function doSomethingElse(): void
    {
        print "Class1::doSomethingElse [$this->attr1,$this->attr2,$this->attr3]\n";
    }
}

// clase derivada 2
class Class2 extends AbstractClass
{
    // atributo
    private int $attr4 = 14;

    // getter y setter
    public function getAttr4(): int
    {
        return $this->attr4;
    }

    public function setAttr4(int $attr4): static
    {
        $this->attr4 = $attr4;
        return $this;
    }

    // implementación de doSomethingElse
    #[\Override]
    public function doSomethingElse(): void
    {
        print "Class2::doSomethingElse [$this->attr1,$this->attr2,$this->attr4]\n";
    }
}

// función externa
function useInterfaceWith(Interface1 $interface): void
{
    $interface->doSomething();
    $interface->doSomethingElse();
}

useInterfaceWith(new Class1());
useInterfaceWith(new Class2());
// los setters "fluidos" pueden encadenarse

    Comentarios

    • líneas 5–10: la interfaz [Interface1] tiene dos métodos;
    • línea 12: la clase abstracta [AbstractClass] implementa la interfaz [Interface1]. Tiene dos atributos con sus getters y setters, implementa el método [doSomething] de la interfaz [Interface1] (línea 43), pero no implementa el método [doSomethingElse]. Por lo tanto, este método se declara abstracto (línea 50). La clase abstracta [AbstractClass] no puede instanciarse y, para ser útil, debe derivarse;
    • líneas 29–39: los setters son “fluidos”: en lugar de no devolver nada, devuelven el objeto [$this]. Esto permite encadenar llamadas (línea 116). El tipo de retorno [static] (PHP 8.0) se refiere a la clase del objeto sobre el que se llamó al método: [(new Class1())->setAttr1(21)] es de tipo [Class1] y no [AbstractClass], lo que permite llamar a continuación a [setAttr3]—un método específico de [Class1]—;
    • línea 54: la clase [Class1] extiende la clase abstracta [AbstractClass] y por lo tanto implementa la interfaz [Interface1]. Proporciona un cuerpo para el método [doSomethingElse], que su clase padre no había definido. También agrega un atributo a los de su clase padre;
    • línea 80: la clase [Class2] hace lo mismo con otro atributo;
    • líneas 106–110: la función [useInterfaceWith] recibe como parámetro un tipo [Interface1] y llama a los dos métodos de esta interfaz;
    • líneas 113–116: se llama a la función [useInterfaceWith] con un tipo [Class1] y luego con un tipo [Class2]. Esto es correcto porque ambos tipos implementan la interfaz [Interface1].

    <?php

declare(strict_types=1);

// un trait que exige algo a las clases que lo usan
trait CounterTrait
{
    // constante del trait (PHP 8.2)
    public const int STEP = 10;

    // atributo estático: cada clase que lo usa tiene el suyo
    private static int $nbInstances = 0;

    // atributo de instancia
    private int $counter = 0;

    // método estático del trait
    public static function getNbInstances(): int
    {
        return self::$nbInstances;
    }

    // método abstracto: la clase que lo usa debe definirlo (firma verificada desde PHP 8.0)
    abstract protected function getName(): string;

    // para ser llamado por el constructor de la clase que lo usa
    private function register(): void
    {
        self::$nbInstances++;
    }

    // método concreto que usa el método abstracto y la constante
    public function increment(): static
    {
        $this->counter += self::STEP;
        print "{$this->getName()}: counter=$this->counter\n";
        return $this;
    }
}

class Car
{
    use CounterTrait;

    public function __construct(private string $registration)
    {
        $this->register();
    }

    // implementación del método abstracto del trait
    #[\Override]
    protected function getName(): string
    {
        return "Car[$this->registration]";
    }
}

class Bike
{
    use CounterTrait;

    public function __construct()
    {
        $this->register();
    }

    #[\Override]
    protected function getName(): string
    {
        return "Bike";
    }
}

// pruebas
(new Car("AB-123-CD"))->increment()->increment();
new Car("EF-456-GH");
(new Bike())->increment();
// cada clase tiene su propio atributo estático
print "number of cars: " . Car::getNbInstances() . "\n";
print "number of bikes: " . Bike::getNbInstances() . "\n";
// la constante del trait es accesible a través de la clase, no a través del trait
print "step: " . Car::STEP . "\n";
try {
    print CounterTrait::STEP . "\n";
} catch (\Error $ex) {
    print $ex::class . ": " . $ex->getMessage() . "\n";
}
// una clase que usa el trait debe implementar el método abstracto
// class Plane { use CounterTrait; }  // Fatal error: Class Plane contains 1 abstract method...

    Comentarios

    • línea 9: desde PHP 8.2, un trait puede declarar constantes. Estas pasan a ser constantes de la clase que usa el trait;
    • línea 12: un trait puede declarar atributos estáticos. Al igual que los atributos de instancia, se copian en cada clase que usa el trait: cada clase tiene su propio contador de instancias;
    • líneas 18–21: un trait puede declarar métodos estáticos. En el código del trait, [self] se refiere a la clase que usa el trait;
    • línea 24: un trait puede declarar métodos abstractos. Toda clase que use el trait debe implementarlos; de lo contrario, debe declararse ella misma abstracta (véase la clase [Plane] comentada al final del script). A partir de PHP 8.0, se verifica la firma de la implementación (tipos de los parámetros y del retorno). Esta es la manera adecuada de imponer requisitos a las clases que usan el trait, en lugar de suponer que tienen un atributo o un método determinado;
    • líneas 33–38: un método concreto [increment] que usa el método abstracto [getName] y la constante [STEP]. Devuelve [$this] (tipo [static]) para que pueda encadenarse;
    • líneas 41–56: la clase [Car] usa el trait, llama en su constructor al método privado [register] del trait e implementa el método abstracto [getName]. Observe el atributo [#[\Override]] en esta implementación: se acepta porque la clase implementa un método abstracto del trait;
    • líneas 58–72: la clase *[Bike]* hace lo mismo;
    • líneas 79–80: cada clase tiene su propio atributo estático [$nbInstances];
    • línea 82: la constante del trait es accesible a través de la clase que lo usa;
    • línea 84: pero no directamente a través del trait: se produce un error.

    9.8. Conclusión

    De los ejemplos anteriores se desprende que los casos de uso en los que usar un trait aporta un beneficio neto no son evidentes. En nuestros ejemplos, siempre podemos prescindir de él sustituyéndolo por una clase. Sin embargo, es útil para factorizar código entre distintas clases, como si ese código perteneciera a una clase padre, sin consumir la herencia simple de la que dispone una clase PHP. Es lo que haremos en la versión 4 del ejercicio de aplicación.
