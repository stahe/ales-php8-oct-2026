    5. Las clases

    Vocabulario: una clase (palabra clave [class]) es un tipo de PHP. Una variable de este tipo se denomina objeto. Un objeto es una instancia de una clase.

    Es en este capítulo donde más se hace evidente la evolución de PHP entre las versiones 7 y 8. PHP 8 introdujo una serie de novedades que hacen que escribir clases sea más conciso y seguro: atributos tipados, promoción de parámetros del constructor, atributos de solo lectura ([readonly]), enumeraciones ([enum]), property hooks y visibilidad asimétrica (PHP 8.4), clonación con modificación (PHP 8.5)... Presentamos estos conceptos a través de los ejemplos, siguiendo la progresión del curso de PHP 7: comenzamos con la clase más básica y avanzamos hasta una clase escrita según las mejores prácticas actuales.

    Comentarios

    • líneas 7–9: en PHP 8, la variable [$obj0] no existe y la operación [$obj0->attr1 = "one"] lanza un error de tipo [\Error] (línea 2 de los resultados) en lugar de crear un objeto. Examinaremos la estructura [try / catch] en el capítulo sobre excepciones. Por ahora, basta con saber que permite capturar el error y continuar la ejecución del script;
    • línea 13: un objeto genérico debe crearse explícitamente con el operador [new]. La clase predefinida [stdClass] es una clase vacía;
    • líneas 15–16: la notación [$obj->attr] designa el atributo [attr] del objeto [$obj]. Si no existe, se crea; esto se denomina atributo dinámico. La clase [stdClass] está diseñada para este fin: se le pueden agregar tantos atributos como se desee;
    • línea 25: la expresión [$obj2 = $obj1], cuando [$obj1] es un objeto, es una copia de referencias: [$obj2] y [$obj1] son referencias (direcciones) al mismo objeto. El objeto mismo puede modificarse a través de cualquiera de las referencias;
    • líneas 27–30: tienen por objeto mostrar que [$obj1] y [$obj2] son dos variables diferentes que apuntan al mismo objeto. [$obj2 = $obj1] copió el valor de [$obj1] en la variable [$obj2] (operación 1 a continuación). El valor de [$obj1] es la dirección de un objeto. Así, [$obj1] y [$obj2] apuntan al mismo objeto. Cuando se manipula una variable [$obj] que apunta a un objeto, PHP manipula el objeto apuntado. Como muestra el siguiente diagrama, podemos modificar el objeto referenciado ya sea a través de [$obj1] o a través de [$obj2]. Esto se ilustra en las líneas 5 y 6 de los resultados;

    • línea 39: la expresión [$obj3 = &$obj2] hace que [$obj2] y [$obj3] estén en la misma dirección que [1 below]. Se podría decir que las dos variables son alias de la misma ubicación de memoria. Ambas apuntan a un objeto, el Objeto A a continuación: [2];
    • línea 50: la operación [$obj2 = new \stdClass()] crea un nuevo objeto, el Objeto B [3 below], y la dirección de este nuevo objeto se asigna a la variable [$obj2] [4]. Como [$obj2] y [$obj3] son dos alias de la misma ubicación de memoria, [$obj3] también apunta al nuevo Objeto B. Esto se muestra en las líneas 31–42 de los resultados;

    • línea 61: ¿es un objeto un diccionario? En PHP 7, la función [count] aceptaba un objeto (con una advertencia) y devolvía 1, lo que no tenía sentido. En PHP 8, lanza un error [TypeError]: [count] acepta solo arreglos u objetos que implementen la interfaz [Countable] (línea 43 de los resultados);
    • línea 66: la función [get_object_vars] devuelve los atributos de un objeto como un arreglo asociativo. El número de elementos del arreglo es igual al número de atributos del objeto;
    • líneas 68–69: se puede iterar sobre un objeto con [foreach], igual que sobre un diccionario. Las claves son los nombres de los atributos y los valores son los valores de esos mismos atributos. Así, un objeto comparte similitudes con un diccionario, pero no es uno. En PHP 7, esta iteración se realizaba con la función [each], que desde entonces fue eliminada;
    • líneas 72–74: el operador de conversión [(object)] convierte un arreglo asociativo en un objeto [stdClass], y el operador [(array)] realiza la operación inversa.

    5.3. Una clase Person sin atributos declarados

    En PHP 7, una clase podía utilizar atributos que no había declarado: bastaba con escribir [$p->firstName = "Paul";] para crear el atributo [firstName] en el objeto [$p], tal como se hace con [stdClass]. Estos atributos dinámicos en objetos de una clase ordinaria están obsoletos desde PHP 8.2: cada vez que se crea un atributo de este tipo, se muestra el mensaje “Deprecated: Creation of dynamic property Person::$firstName is deprecated”. Se eliminarán en una versión futura de PHP. La razón es simple: un error tipográfico en el nombre de un atributo ([$p->firstNam = "Paul"]) crearía silenciosamente un nuevo atributo en lugar de informar el error.

    Hay tres excepciones a esta regla:

    • la clase [stdClass], que acabamos de utilizar, sigue aceptando atributos dinámicos;
    • una clase precedida por el atributo [#[\AllowDynamicProperties]] también los acepta. Este atributo fue diseñado para facilitar la migración de código heredado. No lo utilizaremos en este curso;
    • una clase que define los métodos mágicos [__get] y [__set] decide por sí misma qué hacer con un atributo no declarado.

// respeto estricto de los tipos declarados de los parámetros de las funciones
declare(strict_types=1);

class Person
{
    // los atributos no se declaran uno por uno:
    // se almacenan en un arreglo privado
    private array $attributes = [];

    // se llama al escribir un atributo no declarado: $p->x = value
    public function __set(string $name, mixed $value): void
    {
        $this->attributes[$name] = $value;
    }

    // se llama al leer un atributo no declarado: $p->x
    public function __get(string $name): mixed
    {
        return $this->attributes[$name] ?? null;
    }

    // lo llama isset($p->x)
    public function __isset(string $name): bool
    {
        return isset($this->attributes[$name]);
    }

    // método
    public function identity(): string
    {
        // usa atributos que no han sido declarados
        return "[$this->firstName,$this->lastName,$this->age]";
    }
}

// prueba
// los atributos se crean mediante el método mágico [__set]
$p = new Person();
$p->firstName = "Paul";
$p->lastName = "Langevin";
$p->age = 48;
// llamada a un método
print "person=" . $p->identity() . "\n";
// isset
print "isset(\$p->age): " . var_export(isset($p->age), true) . "\n";
print "isset(\$p->address): " . var_export(isset($p->address), true) . "\n";
// fin
exit;

    Comentarios

    • líneas 6–38: definen una clase llamada [Person]. Una clase es una plantilla que sirve para crear objetos. Se compone de atributos y de funciones llamadas métodos;
    • línea 10: el único atributo declarado para la clase es un arreglo privado (pronto veremos el significado de la palabra clave [private]). Este arreglo almacenará los atributos “no declarados”;
    • líneas 13–16: PHP llama automáticamente al método mágico [__set] cuando se escribe en un atributo que no existe (o que no es accesible). Recibe el nombre del atributo y el valor que se le va a asignar. Aquí, almacena este valor en el arreglo [$attributes]. Los métodos cuyos nombres comienzan con dos guiones bajos se denominan métodos mágicos: no se llaman explícitamente; es PHP quien los llama;
    • líneas 19–22: el método mágico [__get] se llama al leer un atributo que no existe. Devuelve el valor almacenado o [null]. El operador [??] devuelve su operando izquierdo si existe y no es [null]; en caso contrario, devuelve su operando derecho;
    • línea 25: la función [isset] llama al método mágico [__isset];
    • línea 31: el método [identity] utiliza tres atributos que no están declarados en la clase. La palabra clave [$this] designa el objeto al que se aplica el método. Cada llamada a [$this->firstName] desencadena una llamada a [__get];
    • línea 40: se crea un objeto [$p] de tipo [Person] . La palabra clave [new] se utiliza para crear un nuevo objeto. La operación devuelve una referencia al objeto creado (es decir, una dirección). Son posibles varias notaciones: [new Person()], [new Person], [new person]. El nombre de la clase no distingue entre mayúsculas y minúsculas;
    • líneas 41–43: los tres atributos requeridos por el método [identity] se crean en el objeto [$p] mediante el método [__set];
    • línea 45: el método [identity] de la clase [Person] se aplica al objeto [$p]. En el código del método [identity], [$this] hace referencia al mismo objeto que [$p].

    Esta técnica tiene sus usos (objetos de configuración, encapsulación de datos leídos de un archivo), pero no es la forma estándar de escribir una clase. En una clase normal, se declaran sus atributos.

// respeto estricto de los tipos declarados de los parámetros de las funciones
declare(strict_types=1);

class Person
{
    // atributos de la clase
    private string $firstName;
    private string $lastName;
    private int $age;

    // getters y setters
    public function getFirstName(): string
    {
        return $this->firstName;
    }

    public function getLastName(): string
    {
        return $this->lastName;
    }

    public function getAge(): int
    {
        return $this->age;
    }

    public function setFirstName(string $firstName): void
    {
        $this->firstName = $firstName;
    }

    public function setLastName(string $lastName): void
    {
        $this->lastName = $lastName;
    }

    public function setAge(int $age): void
    {
        $this->age = $age;
    }

    // constructor
    public function __construct(string $firstName, string $lastName, int $age)
    {
        // pasamos por los setters
        $this->setFirstName($firstName);
        $this->setLastName($lastName);
        $this->setAge($age);
    }

    // método toString
    public function __toString(): string
    {
        return "[$this->firstName,$this->lastName,$this->age]";
    }
}

// prueba
// creación de un objeto Person

$p->setAge(14);
// identidad de la persona
print "person=$p\n";

    print $p->lastName;
} catch (\Error $e) {
    print "Error: " . $e->getMessage() . "\n";
}

    5.18. Clases abstractas

    Una clase abstracta es una clase incompleta que no puede instanciarse. Debe derivarse para poder utilizarse.

    ¿Cuál es la utilidad de una clase abstracta? A veces tenemos clases que comparten uno o varios métodos, pero difieren en otros métodos o atributos. En tales casos, conviene agrupar todo lo que tienen en común en una clase padre. Por ahora no necesitamos una clase abstracta. Pero supongamos que las clases hijas difieren solo en un método, M: la firma del método sería la misma en todas las clases hijas, pero su implementación sería distinta. Para obligar a las clases hijas a implementar el método M:

    • declararemos la firma del método M en la clase padre. Como la clase padre no sabe cómo implementarlo, anteponemos al método la palabra clave [abstract]: esto significa que la implementación del método M se delega a las clases hijas;
    • como la clase padre no está completamente implementada, también se declara abstracta con la misma palabra clave [abstract]. Esto significa que la clase ya no puede instanciarse. Hay que crear una clase hija que defina la implementación del método M para poder utilizar el cuerpo de la clase padre.

    public function __toString(): string
    {
        // devolvemos la cadena JSON de los atributos
        $attributes = [];
        $this->getRecursiveAttributes($attributes, $this, []);
        // cadena JSON de los atributos
        return \json_encode($attributes, JSON_UNESCAPED_UNICODE);

    public function getAttributes(): array
    {
        return \get_object_vars($this);

    private function getRecursiveAttributes(array &$attributes, mixed $value, array $keys): void
    {
        // análisis del valor [$value]
        // $keys es un arreglo [key1, key2, .., keyn]
        // $value=$attributes[key1][key2]...[keyn]
        // si [$value] es un objeto usamos su método [getAttributes]
        if (\is_object($value)) {
            // atributos del objeto [$value]
            $objectAttributes = $value->getAttributes();
            // ¿hay claves?
            if ($keys) {
                // en [$attributes], vamos a reemplazar $value por el arreglo de sus atributos
                // debemos construir el elemento $attributes[key1][key2]...[keyn]
                // donde $keys es el arreglo [key1, key2, .., keyn]
                // tomamos la referencia del arreglo [$attributes]
                $attribute = &$attributes;
                // recorremos el arreglo de claves
                foreach ($keys as $key) {
                    // tomamos la referencia del atributo
                    $attribute = &$attribute[$key];
                }
                // aquí $attribute y $attributes[key1][key2]...[keyn] son idénticos
                // comparten la misma ubicación de memoria
                // el objeto [$value] se reemplaza por su arreglo de atributos:
                // debemos escribir $attributes[key1][key2]...[keyn]=$objectAttributes
                // lo cual equivale a $attribute = $objectAttributes
                $attribute = $objectAttributes;
            } else {
                // sin claves - estamos al inicio de la exploración del objeto
                // $objectAttributes representa los atributos de 1.er nivel de la clase
                $attributes += $objectAttributes;
            }
            // quizás todavía haya objetos en [$objectAttributes]
            // exploramos los atributos de [$objectAttributes]
            $this->getRecursiveAttributes($attributes, $objectAttributes, $keys);
        } elseif (\is_array($value)) {
            // tenemos un arreglo - analizamos cada uno de sus elementos
            foreach ($value as $key => $element) {
                // agregamos la clave actual al arreglo $keys
                $keys[] = $key;
                // analizamos $element
                $this->getRecursiveAttributes($attributes, $element, $keys);
                // eliminamos del arreglo $keys la clave que acaba de analizarse
                \array_pop($keys);
            }
        }
    }
}

    5.24.1. La interfaz [JsonSerializable]

    Existe una solución mucho más sencilla, proporcionada por PHP: la interfaz predefinida [JsonSerializable]. Examinaremos las interfaces en el próximo capítulo. Por ahora, basta con señalar que una clase que “implementa” la interfaz [JsonSerializable] debe definir un método [jsonSerialize(): mixed]. Cuando la función [json_encode] encuentra un objeto de esta clase, llama a su método [jsonSerialize] y codifica el valor devuelto en lugar del objeto. Lo hace en todos los niveles del árbol de datos. // respeto estricto de los tipos declarados de los parámetros de las funciones
declare(strict_types=1);

// la clase implementa la interfaz predefinida [JsonSerializable]
class Person4 implements \JsonSerializable
{
    // constructor con promoción de parámetros
    public function __construct(
        private string $lastName,
        private string $firstName,
        private int $age,
        // arreglo de objetos [Person4]
        private array $children = [],
    ) {
    }

    // agrega un hijo y devuelve el objeto actual para encadenar las llamadas
    public function addChild(Person4 $child): static
    {
        $this->children[] = $child;
        return $this;
    }

    // método de la interfaz [JsonSerializable]:
    // devuelve el valor que [json_encode] debe codificar en lugar del objeto
    #[\Override]
    public function jsonSerialize(): mixed
    {
        return \get_object_vars($this);
    }

    // __toString: la cadena JSON del objeto
    public function __toString(): string
    {
        return \json_encode($this, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT | JSON_THROW_ON_ERROR);
    }
}
