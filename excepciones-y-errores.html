    7. Excepciones y errores

    Cuando un método de una clase encuentra un error irrecuperable (el archivo no existe, la base de datos no está conectada, la conexión de red está caída), no muestra un error en una consola (archivo, base de datos) sino que lanza una excepción. Las excepciones extienden la clase [\Exception]. Además de las excepciones, el funcionamiento interno de PHP también lanza errores cuya clase base es [\Error]. Ambas clases implementan la interfaz [\Throwable].

    PHP 8 cambió radicalmente el manejo de errores: muchas situaciones que en PHP 7 producían una simple advertencia (y a menudo un resultado absurdo) ahora lanzan un error que se puede capturar. Lo veremos a lo largo de los ejemplos.

    La interfaz [\Throwable] es la siguiente (consulte la documentación):

    interface Throwable extends Stringable
{
    public function getMessage(): string;
    public function getCode(): int;
    public function getFile(): string;
    public function getLine(): int;
    public function getTrace(): array;
    public function getTraceAsString(): string;
    public function getPrevious(): ?Throwable;
    public function __toString(): string;
}

    La función de los métodos de la interfaz es la siguiente:

    Método
    Propósito
    [getMessage]
    Devuelve el mensaje de error
    [getCode]
    devuelve el código de error (un entero)
    [getFile]
    devuelve el nombre del archivo donde se creó el objeto
    [getLine]
    devuelve el número de la línea donde se creó el objeto
    [getTrace]
    devuelve la pila de llamadas a funciones como un arreglo
    [getTraceAsString]
    devuelve la pila de llamadas como una cadena de caracteres
    [getPrevious]
    devuelve el objeto [Throwable] anterior (encapsulado), o [null]
    [__toString]
    devuelve una representación del objeto como cadena de caracteres

    Observe que la interfaz [Throwable] extiende la interfaz [Stringable] que se vio en el capítulo sobre clases. Una clase no puede implementar directamente la interfaz [Throwable]; debe derivar de [\Exception] o de [\Error].

    <?php

// respeto estricto de los tipos declarados de los parámetros de las funciones
declare(strict_types=1);

// muestra el árbol de las clases predefinidas que implementan la interfaz [Throwable]
// nos limitamos a las extensiones siempre presentes en PHP 8.5:
// el núcleo (Core), la biblioteca estándar, la biblioteca SPL, JSON y Random
$extensions = ["Core", "standard", "SPL", "json", "random"];

// las clases predefinidas de estas extensiones que implementan [Throwable]
$classes = array_filter(
    get_declared_classes(),
    function (string $class) use ($extensions): bool {
        $reflection = new ReflectionClass($class);
        return $reflection->isInternal()
            && $reflection->implementsInterface(Throwable::class)
            && in_array($reflection->getExtensionName(), $extensions, true);
    }
);
sort($classes);

// visualización recursiva de las clases hijas de la clase [$parent]
function display(?string $parent, array $classes, string $indentation): void
{
    // los hijos directos de [$parent]
    $children = array_values(array_filter(
        $classes,
        fn(string $class): bool => (get_parent_class($class) ?: null) === $parent
    ));
    foreach ($children as $i => $child) {
        $last = $i === count($children) - 1;
        print $indentation . ($last ? "└── " : "├── ") . $child . "\n";
        display($child, $classes, $indentation . ($last ? "    " : "│   "));
    }
}

print "Throwable\n";
display(null, $classes, "");

    Comentarios

    • línea 13: la función [get_declared_classes] devuelve una lista de todas las clases conocidas hasta ese momento, ya sean predefinidas o no;
    • líneas 16–18: solo se conservan las clases predefinidas (internas), es decir, las que implementan la interfaz [Throwable] y pertenecen a extensiones siempre presentes en PHP 8.5 (línea 9). Otras extensiones agregan sus propias excepciones (por ejemplo, [PDOException] para el acceso a bases de datos, que encontraremos más adelante);
    • líneas 24–36: una función recursiva que muestra las clases hijas directas de la clase [$parent], luego las hijas de cada una de ellas, y así sucesivamente. La función [get_parent_class] devuelve [false] para una clase sin padre: el operador [?:] transforma entonces [false] en [null];
    • línea 29: una función flecha (PHP 7.4), una forma abreviada de función anónima reducida a una expresión;
    • línea 39: se comienza con las clases sin padre: [Error] y [Exception].

    Los resultados muestran dos familias:

    • la familia [Exception]: son las excepciones lanzadas por las bibliotecas y el código de la aplicación. Incluye:
      • [ErrorException], que convierte una advertencia de PHP en una excepción (la usaremos al final del capítulo);
      • [JsonException] (PHP 7.3), lanzada por [json_encode] y [json_decode] con la opción [JSON_THROW_ON_ERROR];
      • [Random\RandomException] (PHP 8.2), iniciada por las funciones de generación de números aleatorios;
      • las excepciones de la biblioteca SPL (Standard PHP Library), un conjunto de clases e interfaces diseñadas para resolver problemas que los desarrolladores encuentran con frecuencia. Forman dos subfamilias:
      • [LogicException] y sus derivadas: errores de programación que se resuelven corrigiendo el código: argumento no válido ([InvalidArgumentException]), valor fuera del rango esperado ([DomainException]), método inexistente ([BadMethodCallException])...;
      • [RuntimeException] y sus variantes: errores que solo se pueden detectar en tiempo de ejecución: índice fuera de los límites ([OutOfBoundsException]), valor inesperado ([UnexpectedValueException]), capacidad excedida ([OverflowException])... ;
    • la familia [Error]: son los errores lanzados por el propio motor de PHP. Incluye:
      • [TypeError]: un valor no es del tipo esperado (parámetro de una función, atributo tipado, valor de retorno, operando de un operador, etc.). Su derivada, [ArgumentCountError], indica un número insuficiente de argumentos;
      • [ValueError] (PHP 8.0): un valor es del tipo correcto pero tiene un valor no válido (por ejemplo, una longitud negativa o cero);
      • [ArithmeticError] y su derivada [DivisionByZeroError]: errores en operaciones aritméticas;
      • [UnhandledMatchError] (PHP 8.0): ninguna rama de la expresión [match] es adecuada;
      • [AssertionError]: falló la aserción de [assert];
      • [CompileError] y su derivada [ParseError]: error de sintaxis en un archivo cargado por [require] o [include];
      • [FiberError] (PHP 8.1) y [Random\RandomError] (PHP 8.2): errores relacionados con las fibras y los generadores de números aleatorios, que no utilizaremos.

    Las dos familias no tienen relación entre sí: una cláusula [catch (\Exception $e)] no intercepta un error [Error]. Solo la interfaz [Throwable] las vincula.

    Comentarios

    • Línea 7: se indica a PHP que informe todos los errores. El parámetro de la función [error_reporting] es el nivel de reporte de errores. Es una combinación de las siguientes constantes (las principales):
    Constante
    Significado
    [E_ERROR]
    Error fatal en tiempo de ejecución: el script se termina
    [E_WARNING]
    Advertencia: el script continúa
    [E_PARSE]
    Error de sintaxis detectado durante la compilación
    [E_NOTICE]
    Nota: algo que podría ser un error
    [E_DEPRECATED]
    Uso de una característica obsoleta, que se eliminará en una versión futura
    [E_USER_WARNING], [E_USER_NOTICE], [E_USER_DEPRECATED]
    Los mismos niveles, activados por el código mediante la función [trigger_error]
    [E_ALL]
    todos los niveles
    • la constante [E_STRICT], que ya no corresponde a ningún mensaje desde PHP 8.0, está obsoleta desde PHP 8.4, al igual que el uso del nivel [E_USER_ERROR] con [trigger_error]: para señalar un error fatal, el código lanza una excepción;
    • línea 8: se configura el código para mostrar los errores en la consola. En producción se hace lo contrario: los errores se escriben en un archivo de registro y no se muestran;
    • línea 12: se intenta acceder a un elemento inexistente del arreglo [$var];
    • línea 14: se produce una división por cero;
    • línea 17: se crea una instancia de la clase [SplFixedArray] de la biblioteca SPL. Esta clase permite crear un arreglo de tamaño fijo con índices enteros;
    • línea 21: se intenta acceder a un elemento inexistente del arreglo.

    <?php

// respeto estricto de los tipos declarados de los parámetros de las funciones
declare(strict_types=1);

// mostramos todos los errores
error_reporting(E_ALL);
ini_set("display_errors", "1");
// rodeamos el código con un try / catch
try {
    $var = [];
    // clave desconocida
    print $var["abcd"];
    // división por cero
    $var = 7 / 0;
    var_dump($var);
    // arreglo de límites fijos
    $array = new \SplFixedArray(5);
    $array[1] = 2;
    $array[4] = "foo";
    // índice fuera de los límites
    $array[5] = 8;
    // verificación
    print "this message will not be displayed\n";
} catch (\Throwable $ex) {
    // \Throwable es la interfaz implementada por todos los errores y excepciones
    // mostramos la excepción
    print "error, message: " . $ex->getMessage() . ", type: " . $ex::class . "\n";
}

    Comentarios

    • El script es el presentado en la sección anterior. Sin embargo, ahora hemos encerrado el código que podría causar errores dentro de una estructura [try / catch]: si el código de las líneas 11–24 provoca (lanza) una excepción o un error, este será manejado por la cláusula [catch] de las líneas 25–29;
    • línea 25: el parámetro de la cláusula [catch] es el tipo de excepción o de error que se desea manejar. Al fijar el tipo en [\Throwable], que es una interfaz, indicamos que queremos manejar cualquier instancia de clase que implemente la interfaz [\Throwable]. Como todas las clases de errores y excepciones implementan esta interfaz, la cláusula [catch] maneja aquí todos los errores y excepciones;
    • línea 15: la instrucción que desencadena el error. En cuanto ocurre una excepción, el control se transfiere a la cláusula [catch]. Por lo tanto, el código que sigue en [try] no se ejecuta;
    • línea 28: la notación [$ex::class] devuelve el nombre de la clase del objeto [$ex].

      • línea 23: maneja un error de tipo [\Exception]. Esto es válido porque el tipo [OutOfBoundsException] deriva del tipo [\Exception];

      • Línea 79: se intercepta el tipo [\Exception]. Esto no es válido porque la clase [DivisionByZeroError] no tiene ninguna relación con la clase [\Exception].

    7.7. La cláusula [finally]

    La estructura [try / catch] puede tener un tercer elemento y convertirse en una estructura [try / catch / finally]. El código de la cláusula [finally] se ejecuta en los dos casos siguientes:

    • la cláusula [try] no lanza ninguna excepción. Se ejecuta entonces por completo y, a continuación, la ejecución pasa a la cláusula [finally], que se ejecuta por completo;
    • la cláusula [try] lanza una excepción. Se ejecuta entonces hasta la instrucción que lanza la excepción. La ejecución pasa luego a la cláusula [catch], que se ejecuta por completo. Después, la ejecución pasa a la cláusula [finally], que se ejecuta por completo.

    Por último, el código de la cláusula [finally] se ejecuta de todos modos. Este escenario es útil en el siguiente caso:

    • en la cláusula [try], el código ha adquirido recursos (archivos, bases de datos, conexiones de red, colas). Estos recursos suelen ser costosos. Por lo tanto, deben liberarse (lo que más a menudo se denomina “cerrar”) lo antes posible;
    • si los recursos se adquirieron en [try], su liberación se realizará en [finally]. Esto garantiza que, en todos los casos (ocurra o no un error), los recursos adquiridos se devuelvan al sistema.

    <?php

// respeto estricto de los tipos declarados de los parámetros de las funciones
declare(strict_types=1);

// [throw] es una expresión desde PHP 8.0: puede usarse después de ?? o en una función flecha
function readAge(array $data): int
{
    $age = $data["age"] ?? throw new \InvalidArgumentException("The age is missing");
    return is_int($age) && $age >= 0 ? $age : throw new \DomainException("Invalid age [$age]");
}

// una función flecha que solo lanza una excepción
$forbidden = fn(string $operation) => throw new \LogicException("Operation [$operation] forbidden");

// datos de prueba
$tests = [["age" => 48], [], ["age" => -4]];
foreach ($tests as $i => $data) {
    try {
        print "test $i: age=" . readAge($data) . "\n";
    } catch (\InvalidArgumentException | \DomainException $ex) {
        // una sola cláusula [catch] para dos tipos de excepciones
        print "test $i: " . $ex::class . ": " . $ex->getMessage() . "\n";
    }
}

try {
    $forbidden("deletion");
} catch (\LogicException) {
    // desde PHP 8.0, la variable de la cláusula [catch] es opcional
    print "the operation was refused\n";
}

// encapsulamiento de una excepción de bajo nivel en una excepción de la aplicación
class DaoException extends \RuntimeException
{
}

function readConfiguration(string $json): array
{
    try {
        return json_decode($json, true, flags: JSON_THROW_ON_ERROR);
    } catch (\JsonException $ex) {
        // la causa original se pasa como 3.er parámetro: no se pierde
        throw new DaoException("Unreadable configuration", 10, $ex);
    }
}

try {
    readConfiguration('{"dsn": "mysql:host=localhost"');
} catch (DaoException $ex) {
    print $ex::class . ": " . $ex->getMessage() . " (code " . $ex->getCode() . ")\n";
    print "cause: " . $ex->getPrevious()::class . ": " . $ex->getPrevious()->getMessage() . "\n";
}

    Comentarios

    • Línea 9: a partir de PHP 8.0, [throw] es una expresión y ya no solo una instrucción. Por lo tanto, puede usarse en cualquier lugar donde se espere un valor: aquí, después del operador [??]. Si la clave [age] no existe, se lanza una excepción; de lo contrario, [$age] recibe su valor;
    • línea 10: [throw] usado en una expresión condicional [? :];
    • línea 14: una función flecha cuyo cuerpo simplemente lanza una excepción. Antes de PHP 8.0 esto no era posible: una función flecha solo puede contener una expresión;
    • línea 21: una sola cláusula [catch] para dos tipos de excepciones (líneas 3–4 de los resultados). Observe que [InvalidArgumentException] y [DomainException] derivan ambas de [LogicException]: un [catch (\LogicException $ex)] habría tenido el mismo efecto;
    • línea 29: a partir de PHP 8.0, la variable de la cláusula [catch] es opcional cuando no se necesita la excepción en sí, sino solo su tipo (línea 5);
    • líneas 35–37: una excepción específica de la aplicación. En los capítulos siguientes escribiremos capas de acceso a datos (DAO, Data Access Object) que lanzarán únicamente este tipo de excepción, sea cual sea el origen del error (archivo, JSON, base de datos);
    • líneas 39–47: la función [readConfiguration] decodifica una cadena JSON. La excepción de bajo nivel [JsonException] se intercepta y se encapsula (línea 45) en una excepción [DaoException]. La causa original se pasa como tercer parámetro al constructor;
    • línea 53: el código que llama solo conoce [DaoException], pero puede recuperar la causa original del error mediante el método [getPrevious] (líneas 6–7 de los resultados).

    7.13. Convertir advertencias en excepciones: [ErrorException]

    A pesar de las mejoras de PHP 8, ciertas anomalías siguen siendo simples advertencias: clave de arreglo inexistente, variable no definida, archivo que no se puede abrir con [fopen]... Estas advertencias no pueden ser interceptadas por un [try / catch]. Sin embargo, se puede instalar un manejador de errores que las convierta en excepciones [ErrorException]. Esto es lo que hace el script [exceptions-11.php]:

    <?php

// respeto estricto de los tipos declarados de los parámetros de las funciones
declare(strict_types=1);

// manejador de errores: convierte las advertencias de PHP en excepciones [ErrorException]
set_error_handler(function (int $level, string $message, string $file, int $line): bool {
    throw new \ErrorException($message, 0, $level, $file, $line);
});

// una clave desconocida ya no provoca una simple advertencia sino una excepción
$person = ["lastName" => "Langevin"];
try {
    print $person["firstName"] . "\n";
} catch (\ErrorException $ex) {
    print "Error: " . $ex->getMessage() . " (line " . $ex->getLine() . ")\n";
    print "level E_WARNING: " . var_export($ex->getSeverity() === E_WARNING, true) . "\n";
}
// lo mismo al abrir un archivo inexistente
try {
    $stream = fopen(__DIR__ . "/nonexistent.txt", "r");
} catch (\ErrorException $ex) {
    print "Error: " . $ex->getMessage() . "\n";
}
// volvemos al manejador de errores de PHP
restore_error_handler();
print "end\n";

    Comentarios

    • Líneas 7–9: la función [set_error_handler] configura un manejador de errores, es decir, una función a la que PHP llamará cada vez que ocurra una advertencia, una nota o una obsolescencia, en lugar de mostrar el mensaje. Recibe el nivel del error, el mensaje de error, el archivo y la línea donde ocurrió. Aquí lanza una excepción [ErrorException] que almacena esta información. El tipo de retorno [bool] es el que especifica la documentación de [set_error_handler]: la función devolvería [false] para que PHP maneje el error normalmente. Aquí nunca devuelve nada porque siempre lanza una excepción;
    • línea 14: la clave [firstName] no existe. En lugar de una advertencia, se lanza una excepción [ErrorException], que es capturada (línea 2 de los resultados);
    • línea 17: el método [getSeverity], propio de la clase [ErrorException], devuelve el nivel del error original (línea 3);
    • línea 21: intentar abrir un archivo inexistente también produce una excepción (línea 4);
    • línea 26: restaura el manejador de errores anterior, en este caso el de PHP.

    Esta técnica la utilizan muchos frameworks PHP (Symfony, Laravel): durante el desarrollo, toda advertencia se convierte en una excepción, lo que obliga al desarrollador a corregir el código. La herramienta de pruebas [PHPUnit] que usaremos más adelante funciona de manera similar: puede hacer fallar una prueba si esta produce una advertencia o una obsolescencia.
